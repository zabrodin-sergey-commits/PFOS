## Архитектурные решения

### ADR-001

**Дата:** 09.07.2026

**Название:** Единая таблица финансовых операций

**Решение**

В PFOS все движения денежных средств будут храниться в одной таблице `operations`.

Тип операции будет определяться специальным полем, например:

- Доход
- Расход
- Перевод
- Погашение кредита
- Начисление процентов
- Инвестиция
- Дивиденды

**Причина**

Любое движение денег является финансовой операцией. Такой подход делает систему проще, гибче и позволяет строить любую аналитику на основе одной истории операций.

**Последствия**

- Не потребуется создавать отдельные таблицы для доходов и расходов.
- Любой банковский импорт будет загружаться в одну таблицу.
- ПИ сможет анализировать всю финансовую историю семьи в одном месте.

---

### ADR-002

**Дата:** 09.07.2026

**Название:** Владение недвижимостью через отдельную таблицу

**Решение**

Связь между людьми и объектами недвижимости реализуется через отдельную таблицу `property_owners`.

Каждая запись содержит:

- объект недвижимости;
- владельца;
- долю собственности.

**Причина**

Один объект недвижимости может принадлежать нескольким людям, а один человек может владеть несколькими объектами.

**Последствия**

Архитектура поддерживает совместную собственность без изменения структуры базы данных.

# Принципы разработки PFOS

## 1. Польза важнее технологий

Мы не используем сложные технологии ради самих технологий.
Каждое решение должно приносить практическую пользу семье.

## 2. Данные принадлежат семье

Все финансовые данные хранятся локально.
Пользователь полностью контролирует свою информацию.

## 3. История никогда не теряется

PFOS хранит историю изменений.
Удаление данных не является обычной операцией.

## 4. Любое решение должно быть объяснимым

Если ПИ дает рекомендацию, он обязан объяснить,
на каких данных и расчетах она основана.

## 5. Простота важнее сложности

Если существует два решения,
мы выбираем более простое,
если оно не ухудшает результат.

## 6. Автоматизация должна экономить время

Каждая новая функция должна избавлять пользователя
от ручной работы.

## 7. PFOS развивается вместе с семьей

Архитектура должна позволять добавлять новые возможности
без полной переделки системы.
